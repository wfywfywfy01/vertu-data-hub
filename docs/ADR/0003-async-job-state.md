# ADR 0003：Redis/Celery 传递任务，PostgreSQL 保存权威状态

## 状态

已接受，2026-08-19。

## 背景

文档、图片、音频和视频处理耗时差异大。仅使用 Web 请求会超时，仅使用队列状态会在消息过期后失去审计依据。

## 决策

- 使用托管 Redis 和 Celery，队列分为 `documents`、`images`、`videos`、`exports`。
- PostgreSQL 保存任务、尝试次数、进度、错误、输入输出和最终状态，是唯一权威状态。
- API 先以幂等键创建数据库任务，再投递消息；worker 使用任务 ID 获取并锁定任务。
- 任务支持超时、有限重试和死信处置；Redis 中不存在消息不能被解释为成功。
- 视频 worker 独立扩缩容，外部模型只接收必要的关键帧、音轨片段或文本片段。

## 后果

系统增加 Redis 和 worker 运维项，但长任务不会阻塞页面，且失败可以定位和重放。
